# 阅读器语义内容与坐标规范

本文规定章节正文、字符位置和持久化定位数据的共同含义，约束当前实现及后续重构。
`ReaderChapterSource.semanticContent` 是内容处理完成后的正文字符串，是阅读、标记、搜索、导航和朗读计算正文位置的共同依据。

## 基本原则

- **统一解析规则**：各功能使用同一定义的正文，避免各自提取 HTML 文字而产生坐标差异。
- **内容与呈现分离**：固定处理后的章节输入，排版变化不得改变正文及其位置；内容变化必须使相关缓存失效，并重新校验旧定位。
- **位置与文本身份分离**：位置合法不等于目标文字仍正确；已有位置能否复用，须由当前文字及文本锚点验证。
- **兼容性须可验证**：存储格式未变、编译通过或文件符合格式标准，均不能单独证明定位兼容。

## 架构职责

处理顺序：`ContentProcessor → ReaderChapterSourceParser → ReaderChapterSource`；HTML 部分由 `JsoupReaderHtmlParser` 解析。

| 组件 | 职责与边界 |
| --- | --- |
| `ContentProcessor` | 执行净化、简繁转换、重新分段及正文处理，确定最终内容 |
| `MixedContentSegments` | 识别普通文本与 `<usehtml>` 的边界，保持两类内容各自的处理规则 |
| `ReaderChapterSourceParser` | 组装章节正文、渲染块及正文位置，分离标题与正文坐标 |
| `JsoupReaderHtmlParser` | 在一次遍历中生成 HTML 正文和行内元素位置，供文字提取与渲染测量复用 |
| `ReaderSemanticContract` / `ReaderSemanticLocation` | 检查正文与范围的一致性，执行严格匹配及 UTF-16 边界修正；不解析或修复 HTML，不实现模糊重定位 |
| `ProcessedContentEditor` / `ReaderHtmlTextEditor` | 将编辑范围临时映射到文本节点，校验修改结果；不持久保存 DOM 或逐字符映射 |

不同入口可以分别解析章节，但不得另建不同的正文提取规则。Android 生产入口使用共享的 Jsoup 解析规则；
core 中的正则 HTML fallback 仅保留为旧调用兼容路径。契约校验不在翻页热路径执行。

## 正文与坐标规则

1. 正文位置采用 Kotlin `String` 的 UTF-16 code unit 偏移，范围为 `[start, endExclusive)`。
   合法偏移为 `0..semanticContent.length`，选区边界不得切开代理对。
2. `characterCount` 必须等于 `semanticContent.length`；文本、图片及有字符长度的行内元素，必须对应正文中的正确区间。
3. 标题使用独立坐标，不计入正文位置；标题显示、分段和样式变化不得平移正文坐标。
4. 已有换行、占位字符和空白处理规则属于兼容约定，未经差异验证不得调整。

| 内容 | 正文规则 |
| --- | --- |
| 普通文本 | 保留处理后的文字；已注入的段首缩进、角色标签占字符位置 |
| HTML 文本 | 解码实体，沿用现有空白合并和段首空格处理；`pre` 保留内部空白 |
| 图片 | 有资源路径时占一个 U+FFFC；缺路径时不占位 |
| 换行 | 保留现有 HTML 段落、`br` 及外层 HTML 块结束产生的换行，不合并或删减 |
| 非正文内容 | 标签本身、ruby 的 `rt/rp`、BGM 视觉胶囊及 `[newpage]` 不占正文字符 |
| 隐藏节点 | 在输入 DOM 清理阶段移除，不进入后续正文 |

字号、密度、主题、边距和分页属于呈现输入。净化、简繁、重新分段、HTML 解释、隐藏节点清理，以及当前实现中的文字缩进和角色标签注入，属于可能改变正文的输入。

## 内容操作与消费边界

- 高亮、划线和搜索在最终正文上定位，不在序列化 HTML 或简单剥标签的结果上定位；无有效匹配或边界非法时不绘制选区。
- 简繁转换和富文本替换规则只修改文本节点，不修改资源、锚点和样式属性。替换规则按节点执行，不支持跨节点匹配；规则顺序、regex/JS 行为和异常处理保持兼容，同一正则规则共享超时预算。
- 重新分段仅处理普通文本，不跨越 HTML 块合并段落。最终段落生成与编辑验证必须使用相同规则。
- 选区编辑只处理能够直接映射到文本节点的范围或插入点。跨段、跨通道、替换或删除图片/结构性换行，以及涉及空白折叠的节点，按保守边界拒绝处理。
- 编辑后必须重新解析；仅当 HTML 和整章正文均严格符合预期修改结果时接受输出。失败时保留原文，返回不支持原因并记录日志。
- 朗读消费正文及其绝对位置；朗读单元可以省略尾部分隔符，但不得另建 HTML 文字提取规则。
- 链接先分类再导航：相对路径、锚点及已有 MOBI/KF8 定位协议用于书内跳转；HTTP、HTTPS、mailto、tel 及协议相对地址按外链处理，后者打开时补 HTTPS。脚本、data、控制字符及未知协议不自动导航。

## 兼容性要求

### 后向兼容：新实现读取旧数据

- 保留已有持久化字段、坐标单位和章节模型，不将页码、字节位置或字形索引写入正文位置字段。
- 书签、笔记跳转前校验来源、章节、目标文字及已保存的有效上下文；不匹配时使用已有重定位逻辑，无法确定时进入确认流程，不自动覆盖原位置。
- 页书签文本不要求从保存位置开始；唯一且包含该位置的完整页文本可以作为校验证据。无法匹配的历史页文本不得被视为定位成功。
- 无可靠文本锚点时，只能修正越界与非法字符边界，不能保证恢复原句。重建导航正文时，须采用与阅读器一致的处理设置及角色标签输入。

### 前向兼容：旧实现读取新数据

- 当前改动继续使用已有存储格式，不持久化 DOM、内部渲染索引或新的坐标类型。
- 格式可读不等于位置准确；不得承诺旧版本在不同正文处理规则下仍能精确解释新位置。
- 后续若改变字段含义、正文计数或存储格式，必须单独定义旧版本读取、降级与迁移策略，并建立双向版本验证；不能仅凭字段名称未变认定兼容。

### 缓存与设置变化

- 搜索复用条件必须覆盖书籍、查询选项、标题模式、简繁、HTML 解释、净化开关、重新分段、缩进及内容修订。
- 一轮搜索固定相关设置；输入变化后停止旧扫描，不再复用旧缓存或会话。正文保存/删除、处理记录变化及规则重载须触发失效。
- 当前使用全局内存计数器进行保守失效，不新增持久化版本号，也不先解析全书计算缓存哈希。初次 EPUB 提取仅填充同一内容的缓存，不视为正文变更。

## 验证要求

- 对固定输入校验精确正文、字符数量、元素范围及锚点；纯呈现变化必须保持这些结果一致。
- 正文规则或定位行为变更须覆盖高亮、搜索、导航、朗读与编辑的相关回归；有意改变的坐标必须明确说明兼容影响。
- 自动化测试只依赖仓库内自编写的小型 EPUB fixtures，不依赖本地书库。现有 Verify 工作流执行测试、lint、架构检查和 Debug 构建。
- JVM 文本与资源测试不替代 Android PFD 读取、真实 KF6/KF8、旧数据升级及设备行为验证。文件格式合规性与阅读器行为兼容性应分别验证。
