# 漫画英日韩混排校准

## 样本与口径

2026-10-28 使用用户提供的三张公开气泡示例图，在 PLK110 上通过正式翻译 Repository、
应用内配置的 `deepseek-flash`／OAI Chat Completions 执行。思考关闭；原图与编号裁剪表
随一次逻辑请求发送，随后分别本地擦字和覆盖合成。它们是示例网格，不能替代真实漫画回归集。

正文有 33 个物理区域，包括一个只有纵向省略号的窄叙述框。当前三图均识别到 32 个含正文
的候选，纯省略号框未检出，保留原图。这不等于字符识别率；标题、底部分类标签及艺术字不计入
32 区域的方向检查。没有为日韩文字建立逐字真值，也没有把英文人工框按比例套用于其他图。

日文图大部分是**横排分行**；左上“……大丈夫？”和中下窄气泡“……ごめん……”是真正的
竖排。韩文也有两个相应的竖排样本。英文窄气泡里的 `I'm / sorry` 是横排单词折行，不能按
窄高外形判为竖列。相连气泡的开头片段与后续句子应保持不同区域。

## 基线问题

v2 生产路径日文完整管线通过，一次请求约 12.248 秒，但 32 个正文区域中有 26 个横排区域
被误判为竖排。显式改为 `sourceDirection=HORIZONTAL_ROWS/VERTICAL_COLUMNS` 后重测，
计划仍可解析、坐标仍有效，但日文有 24 个横排区域被误判，证明单靠方向枚举和提示词不足。
这会同时选错源字号基准和译文方向；不能把计划合法当作视觉成功。

同一 v3 提示词下，韩文 32 个已匹配正文的方向均正确（两个竖排），一次完整管线约
11.780 秒；英文 32 个已匹配正文均为横排，一次约 13.918 秒。两者均为一次 AI 请求、
思考计时 0。另有一次早期韩文请求在文本行校验处失败，没有导出可用计划；没有捕获该次
完整原始响应，因此不能确定具体格式原因，也不将失败计为成功识别。

## 本次改动与边界

- 编号候选增加原图墨迹行列方向提示。按分离行／列中的墨迹延展程度加权比较，差异不足、
  空白、过密和近方形证据不提供提示。提示送给 AI，客户端不强行改写 AI 的目标行列。
- 源方向和译文方向分开；缺省译文跟随源方向。独立文字翻译后的排版保持此前识别的源方向，
  防止后续模型改用另一源字号基准。
- 兼容远端将换行嵌入 `lines` 项、tab 和空格式行的情况，标准化后继续校验文字保全、单词和
  Unicode 字素边界；其他控制字符仍报错。错误附带区域 ID。
- 手动校准可选 `mangaAiCalibrationLanguage=en|ja|ko`，默认 en。完整管线捕获公开样本的
  内容响应，供定位返回格式问题；不导出密钥、HTTP 正文或思考内容，不改用户漫画设置。

该提示不是 OCR，也不是通用方向分类器。规则字阵、旋转、注音和紧密排列可能没有足够证据。
源字号仍是原图估计，不能视为字体文件的精确 em；合成中可见局部边框缺口、底纹修复痕迹，
艺术字可能合并或漏识。方向修正不代表这些问题已解决。

墨迹测量中该候选无明确方向提示，没有被客户端强制改向。此前英文提示词单独测试为横排，
两次结果不一致，不能声称这条路径已经稳定解决方向问题。后续应增加真实漫画、多次重复和
窄 Latin 单词行的验证，不能将语言或气泡高宽比当作强制规则。

的逐像素真值，故不提供这两图的像素定位准确率或字符准确率。

## 复现与产物

沿用 [英文校准入口](manga-ai-calibration.md#可重复的手动入口)，加入
`-e mangaAiCalibrationLanguage ja` 或 ko。模式 `pipeline` 使用正式 Repository，生成 SMART、
PATCH、诊断图和发布快照；默认测试仍 skip，不调用付费服务。原始内容响应以 response-N.json
和 response.json 导出。`replay` 可加 `mangaAiCalibrationReplayRaw=true`，离线重放未归一化的
原始响应；不调用外部 AI。

本地忽略产物在 `build/reports/manga-translation/calibration-cjk/`，`ja-v3/ko-v3/en-v3` 保存方向
提示词单独生效时的结果，`ja-ink/ko-ink/en-ink` 保存加入墨迹提示后的正式管线结果，
`direction-results.json` 为人工逐候选方向核对结果；`japanese-direction-comparison.png` 为日文
原图、仅提示词、加入墨迹证据的局部对照。报告须区分模型原文识别、方向判断、几何和最终
擦字效果，不能只数框。
