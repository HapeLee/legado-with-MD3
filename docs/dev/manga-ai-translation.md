# 漫画翻译

## 当前实现

阅读器菜单顶栏的翻译按钮打开翻译设置。自动翻译提供总开关与独立漫画开关，默认均关闭；
同时开启后，图片加载／预加载完成就进入翻译队列，不依赖当前阅读位置。单页翻译入口在图片长按菜单，
整章操作保留在设置面板。处理期间显示原图，完成后在同一图片槽位换成派生 PNG。
页面的原始 URL、加载请求身份、阅读进度与图片槽位不因译图改变。
通用翻译参数直接位于“设置 → 漫画设置”的“漫画翻译”分组。漫画默认继承，也可在阅读器关闭
“使用全局翻译设置”维护本书配置；本书自动翻译开关和术语独立保存。

已发布译图与待应用的翻译设置分别保存。修改语言、模型、术语、定位方式、排版或字号不会撤下上次成功译图，
重新进入阅读器也优先恢复它；重新翻译／排版成功后才替换。译图始终显示，不再提供「显示译图」开关。
原图内容摘要改变后不复用旧锚点，清除本书结果仍会删除译图与锚点。

本地擦字／覆盖模式提供「仅重新排版当前页」「重新排版本章已有译文」：复用上次保存的原文、译文、源定位、
原文字号估算，旧版本的局部几何可从原图本地升级；不解析当前 AI 配置，也不调用在线文字或图片服务。
本章操作跳过没有文字锚点的页面。
此操作应用本地擦字引擎、排版与字号；语言、翻译模型和术语调整通过翻译／强制重译应用。整页 AI 编辑没有文字锚点，不能直接重排。
SMART 可选本地快速处理、MI-GAN 或通用 LaMa，模型按需下载，背景单独缓存；
配置、许可证和端侧验证见 [擦字引擎](manga-inpaint-engines.md)。

新 UI owner 是 `feature/manga/translation`。既有 `ui/book/manga` 只负责接线；
`MangaTranslationGateway` 承接配置、术语及翻译结果，数据实现拥有文件、Room 查询、ML Kit 和网络。
本次不创建 Gradle 模块，不迁移阅读渲染核心，不宣称已经实现 KMP。

## OCR 与翻译模型

翻译面板将 OCR 路线与文字翻译模型分别配置，设置按书保存：

- AI 识图：默认「跟随翻译模型」保持旧版合并请求。显式选择支持图片输入的模型后，
  先由该模型识别原文和紧框，再向翻译模型发送纯文字。两个模型可以来自不同供应商。
- 端侧 OCR：选择内置 ML Kit，或按需下载 PP-OCRv5 mobile、PP-OCRv6 Small／Medium（中、日、英文）和 V6 日文漫画版。
  每套包含检测器、识别器、匹配字典；大小分别约 20.5／29.7／82.6／29.7 MiB。
  下载进度、校验、取消、失败重试与删除均在面板内管理，可同时保留多套模型，按书保存选择。
  漫画版是社区日文微调，不开放其他语言。
  另可下载 V5 mobile 韩文（17.5 MiB）、东斯拉夫语（12.1 MiB）与 V6 Tiny（6.0 MiB）。
  Tiny 当前字典支持中、英文，不包含日文；专用语言版使用各自匹配字典，不复用通用版字典。
  下载和删除按指定模型执行，切换引擎不隐藏进行中的取消按钮、不撤下已发布译图。
  固定权重提交、大小、SHA-256 及目录修订见 `MangaPaddleModelCatalog`；V5 沿用原目录。
  V6 套件复用其他已装套件中经过校验的相同文件来减少网络下载，但各自保存独立副本以便安全删除。
- 云端 OCR：百度智能云、腾讯云、PaddleOCR 官方在线 API 与 PaddleOCR 兼容同步服务。
  使用云端返回的原文／文字行位置，再由既有翻译模型翻译纯文字，本地排版与重排不变。
  凭据独立全局配置，以 Android Keystore AES-GCM 加密后存于 `noBackupFilesDir`，不进入按书设置或锚点缓存。
  配置入口、接口与验证范围见 [云端 OCR 接入](manga-cloud-ocr.md)。
  ML Kit 保留内置方式，避免对无 Google Play 服务设备引入新的依赖。
- 翻译模型：复用 AI 设置中的供应商与模型，仍通过 Chat Completions、Responses、Anthropic 等现有适配处理；
  本轮没有新增 Google Translate、DeepL 或离线 LLM 翻译引擎。

端侧识别不会将图片上传给文字翻译模型。图片编辑类合成仍按所选合成方式调用图片供应商。
模型未下载、校验失败或 native 不可用时明确报错，不静默切换引擎。
切换 OCR 配置不会撤下已有译图；应用新引擎到已译页需要重新翻译。「仅重新排版」继续复用已保存锚点。
文件版本、授权与实现范围详见[模型研究与接入说明](manga-local-vision-models.md#可选-ocr-与独立翻译模型)。

## AI 过程与思考强度

漫画翻译面板复用正文的 `AiReasoningModeButton` 和 `AiThinkingCard`：使用全局配置时跟随漫画设置分组中的强度，
本书单独设置时可用右上角灯泡选择。AUTO 沿用模型默认参数，显式选择覆盖文字分析请求的强度。
强度只通过既有协议兼容逻辑发送，
实际支持的等级及能否关闭思考由模型决定；通用模型未标记 reasoning 能力时提示检查 AI 设置，
已知 DeepSeek Flash／V4 使用下文的专用兼容策略。不能把 UI 选择描述为服务端必然执行。

文字分析使用现有 Chat Completions／Responses／Anthropic 流式入口，在同一次请求中分别收集服务商返回的
reasoning 和译文 JSON。思考默认收起，可展开查看；正文数据仍须完整接收并通过原有校验后才能发布译图。
没有返回思考内容时显示说明，不推测或补造内容。只返回思考而没有译文、异常工具调用或过大的输出明确失败，
不自动改用非流式接口重复付费。请求使用既有 120 秒网络限时和 180 秒整体限时，取消会沿用共享 SSE 的关闭连接逻辑。

界面显示总耗时、当前阶段耗时、最近文本请求的模型与已接收数据量。诊断更新最多约每 100ms 一次，
思考显示保留最近 64 Ki 字符并提示截断，译文 JSON 上限 4 Mi 字符。
最近请求的思考在本次阅读会话中保留到下次操作，可在完成／失败后查看；不写入长期译图／术语文件。
关闭面板不中断任务，取消任务或切书会拒绝迟到更新；已有译图继续保留。

显式思考强度参与新文字分析的缓存身份，AUTO 保留旧默认缓存身份。调整强度不撤下已发布译图，
也不触发付费请求；下次翻译按新设置处理。「仅重新排版」忽略这些 AI 设置，始终复用保存的文本和锚点。
整页图片编辑不依赖文字思考设置，当前图片编辑流程尚未接入同样的思考过程／强度控制，界面明确提示这一限制。
降低文本强度可能减少模型等待时间，但不能控制图片生成耗时；流式展示本身也不等于已经测得真实服务提速。

共用思考滑块将浮点回调四舍五入到最近档位，不再直接截断。不同控件宽度下，像素到离散刻度的
换算可能略小于整数，截断会把目标档位错误归到前一档。漫画、正文和其他使用同一控件的入口共用此修正。
Compose 指针输入回归覆盖全部七档的正反拖动、紧凑／展开窗口，以及 Material 和 Miuix 引擎，
展开窗口另逐一覆盖 380–430dp 的可用宽度；原无障碍设置档位的测试仍保留。
该修正的 18 项定向测试、Debug 打包、架构门禁与差异检查通过，尚未重新进行真机触摸验收。

### DeepSeek Flash / V4 参数校正

2026-10-27 对照 [DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、
[Chat API](https://api-docs.deepseek.com/api/create-chat-completion/)、
[Responses API](https://api-docs.deepseek.com/api/create-response/) 与
[Anthropic 兼容说明](https://api-docs.deepseek.com/guides/anthropic_api/) 校正了请求体。
原通用实现的 OFF 没有生成 DeepSeek 关闭开关，缺少 reasoning 能力标记或自定义供应商身份不能被识别时也不发送强度参数，
且通用七档并非七个不同的 DeepSeek 档位。修复前的 5 项请求体测试中 4 项失败，验证了这个差异。

| 软件选择 | DeepSeek 实际请求配置 |
| --- | --- |
| 自动 | 不额外指定；漫画任务若继承了模型默认强度，按继承值发送 |
| 关闭 | Chat／Anthropic 发送 `thinking.type=disabled`，不混入启用思考的 effort；Responses 发送 `reasoning.effort=none` |
| 低 | 启用思考，effort 为 `low` |
| 中／高／极高 | 启用思考，effort 为 `high` |
| 最大 | 启用思考，effort 为 `max` |

Chat 使用 `reasoning_effort`，Anthropic 使用 `output_config.effort`，Responses 使用 `reasoning.effort`；
DeepSeek Responses 不发送通用 OpenAI 的 `reasoning.summary` 字段。模型特定分支由已知 Flash／V4 型号识别，
支持命名空间前缀和版本别名，不依赖手工导入的 reasoning 标记；旧 R1／reasoner 和其他厂商保留原逻辑。
流式、非流式和漫画参数诊断复用同一构造逻辑，面板只显示公开的思考控制字段，不显示密钥、请求头或图片。
若请求关闭但服务端仍回传思考，面板给出明确提示，便于检查中转平台是否转发或执行该设置。

官方 `deepseek-flash` 的默认强度为 high，低强度仍会返回思考；强度不是严格的思考长度上限。
参数显示和序列化测试只能确认客户端构造值，不能证明任意中转平台执行了设置。旧译图继续持久保存，
验证新参数请显式重新翻译当前页，不以已缓存的结果作为新调用证据。

## 可组合的路径

| 选项 | 实际行为 |
| --- | --- |
| AI 定位 | 普通页整图、长条漫画按分析窗口交给支持图片输入的 AI，一次返回原文、译文、紧原文框、方向和短术语，不要求规划译文排版 |
| 本地定位 | 内置 ML Kit 日文／中文／韩文／拉丁文字识别器先提供原文及文字行框；仅将编号和原文交给 AI 翻译，客户端按编号合并并保留检测结果 |
| 本地擦字排版 | 在紧文字行框内提取高对比笔画，用邻近非文字像素填充，再测量绘制译文 |
| 覆盖排版 | 采样底色遮盖原文与排版区域，程序绘制译文 |
| AI 修复后排版 | 图片编辑模型擦字；仅将指定擦字矩形的像素贴回，程序嵌字 |
| AI 区域替换 | 图片编辑模型按确定译文处理，客户端仅贴回擦字与排版矩形 |
| AI 整页编辑 | 图片编辑模型直接翻译和编辑图片，独立于定位及文本模型；可沿用已有术语，当前不自动提取新术语 |

本地识别不依赖 GMS 动态下载；四种内置模型会增加 APK 体积。AI 定位支持现有 Chat Completions、Responses、
Anthropic Messages 的图片输入格式。本地定位可搭配纯文字模型；即使模型有 vision 标记，文本翻译阶段也不发送图片或坐标。

## 识别、翻译与排版的职责

文本翻译请求不再要求模型回传已有的定位数据。本地识别先完成原文和区域划分，再发送
`{id, original}` 列表；响应只含 `{id, translation}` 和短术语。必须逐一对应所有编号，
缺失、重复或额外编号均拒绝发布。原文、顺序、框、方向和字号锚点由客户端保留，AI 无法覆盖它们。

AI 定位仍为每个分析窗口一次视觉请求：读取、翻译并给出紧原文框。不再要求 `layoutBox`、
逐行 `eraseBoxes`、译文换行或字号。缺省排版框和擦字框先使用原文框；客户端估算原文字号，
然后在有限的均匀背景中扩展排版区域。旧的完整响应和已保存锚点仍兼容。

定位提示词明确一个区域对应一段完整原文：同段的所有行／列合并，包含首尾笔画、标点、附加符号和关联小注音，
不把气泡边框、画面或大片留白当作原文。保留原文换行，译文不机械照搬源换行；不同气泡、分镜和说话者分开。
`vertical` 只表示原文字符流方向，多行横排放在竖向胶囊内仍为 false，不用框或气泡的长宽比推断方向。

视觉请求附带实际发送 JPEG 的宽高，而非原图尺寸：X 向右、Y 向下，左右坐标按宽归一化，上下按高归一化到 0..1000。
长图窗口包含上下文时仍使用整张附图坐标，中心归属范围只负责筛选，不能作为坐标新原点。
本地识别的纯文字请求不发送图片尺寸，也不增加定位任务。协议、返回字段和单次分析请求数不变。
提示词变更不自动作废已付费的分析缓存；验证当前已有页面需明确「重新翻译当前页」，会重新请求 AI。
「仅重新排版」继续复用旧识别结果，不能验证新提示词的定位效果。
提示词调整另执行 62 项相关定向用例、Debug 打包、架构门禁和差异检查，均通过；新增请求检查验证
高分辨率预览和长图各窗口的尺寸元数据与实际 JPEG 一致，本地识别仍不发送图片尺寸。
这些检查只验证客户端请求与兼容行为，尚未用真实供应商对比定位准确率、推理耗时，也未重跑全量 Lint。

当前没有强制改成「视觉识别 API → 文字翻译 API」两个付费轮次。额外轮次会增加往返等待，
是否更快需用真实模型测量；独立识别缓存和可单独重翻译原文可作为后续切片。
本次去掉的是模型规划排版和重复输出定位数据的职责，不承诺消除模型自身的全部思考。
图片编辑支持 OpenAI Images、Gemini Interactions／generateContent、Seedream、Qwen Images、xAI 和硅基流动原生协议，
路径可配置，模型从 AI 设置中启用「编辑图片输出」的模型中独立选择。协议差异与供应商设置见 [AI 图片供应商](ai-image-providers.md)。
仅支持看图不代表能够编辑输出图片。没有自动服务降级或图片生成重试。

## 数据与缓存

所有派生数据位于应用私有 `files/manga-translation/<book hash>`，原图始终不覆盖。

- `book.json`：按书配置、术语、用户术语修订版本；原子写入，不复制 AI 密钥。
- `analysis-bands-v2.json`、`page2` JSON：分析窗口及经过唯一 ID、完整性、坐标范围、擦字区域验证的原文和译文。
- `edit2.png`：AI 编辑的分析预览，独立于程序字号缓存，修复背景后调整字号不会再次调用图片服务。
- `roi2` PNG：原尺寸下完整文字区域的擦字与排版结果，供不同输出块复用。
- `<source hash>.published.json`：该原图最后成功发布的译图，以及完整文字锚点快照；不依赖当前设置或模型仍然存在。
- `<image>.metadata.json`：每个不可变译图对应的锚点快照，便于恢复此前已经生成的排版版本。
- PNG：可重建译图，强制重译使用新文件名，防止正在使用的图片被原地改写。

分析身份包含原图 SHA-256、语言、定位来源、文本模型配置指纹、用户术语修订版本，以及显式文本思考强度。
合成身份另包含排版方式、字号、图片模型配置指纹及接口路径。切换显示或自动翻译开关不会重做分析；
程序模式改字号或擦字方式可以复用已付费的分析结果。保存人工术语使下次翻译重新分析，但保留当前已发布译图；
自动发现不能覆盖既有译名。
删除本书结果保留配置和术语。未添加专门的翻译数据同步／备份逻辑，现有备份路径的覆盖范围尚未验证；
当前没有自动的译图磁盘容量淘汰。

旧格式只有设置相关的缓存键，首次按匹配设置命中时可收养旧译图；缺少快照的旧译图需要再执行一次翻译来建立锚点，
匹配的分析 JSON 仍可复用。旧设置已经丢失且未建立发布记录的历史文件，无法可靠反推出属于哪张原图。
文本及局部图片采用同目录临时文件、同步和原子替换写入；提交失败向调用方报告，保留上一份发布记录。

## 本地擦字与字号

当前内置 `detector-v4-s_int8.onnx`（11,120,765 字节，固定 SHA-256）并使用 ORT Android 1.28.0 在 CPU 推理。
模型分辨气泡、泡内文字和泡外文字，输出框而非轮廓。会话与输入缓冲串行复用，空闲 30 秒释放 native 会话；
原生前向无法取消，输入位图保留到返回后再检查协程取消。加载失败显式报错，不把能力缺失当作无字页。
空闲释放受系统调度影响，设备深度待机时可能延后；不会为该模型新增生产环境的电源豁免。
代码／模型来源、Apache 许可证、ORT MIT 许可证与第三方声明放在 `assets/manga-vision/`。

AI 定位请求附带本地物理气泡候选，要求相连气泡分开并连贯翻译；本地定位则在翻译前按气泡归属合并 OCR 行，
不同气泡保留不同编号，未归属文字仍保留。原文行文本与框随分析快照保存，不能由 AI 替换客户端可信掩膜。
检测框约束 ROI，移植的内部估算器使用图像边缘和颜色恢复轮廓；椭圆仅作为恢复约束，不直接当作可信结果。
共享颈部按实例中心分配；分割后的掩膜仍须覆盖至少 72% 的各原文成员，才允许用于局部合成。
单个搜索不超过 1 Mi 像素，整页预算最高 4 Mi 像素；掩膜压缩为 start/count 游程并持久化，有尺寸、顺序及总量检查。

可信掩膜限制排版和擦字更新像素，覆盖模式只处理原文范围与实际译文行列，不再铺整个气泡外接矩形。
模型无可靠轮廓时保留既有矩形／胶囊处理；同一分析版本重排复用掩膜，不重复推理或在线翻译。
发给图片编辑服务的区域描述剔除掩膜和本地行数据，避免把大数组放进提示词。


本地漫画检测模型、参考项目源码与分阶段接入建议见
[本地视觉模型评估](manga-local-vision-models.md)。当前实现已接入其 RT-DETR 与 overlay 固定区域字号／形状排版路线。

重叠圆形气泡、多容器对白分组及实例轮廓硬约束尚未实现；研究方案、当前限制和待验收场景见
[容器、对白分组与边界约束](manga-container-flow-layout.md)。完整的语义对白分组仍为设计；当前局部几何版本为 v6。

文字定位仍来自 AI 或本地识别框。擦字和覆盖在原文字行周围增加有限余量（短边 12%，2–24 原图像素），
将描边、抗锯齿及轻微定位偏差纳入处理；这一范围同时参与 ROI 解码和最终贴回，不能只扩大中间位图。
本地擦字降低前景对比阈值，先寻找与原文字框内笔画相连的前景，再膨胀掩膜；
新增余量内不相连的画线不会自动成为擦字目标。紧裁切的高密度字块不再直接跳过。
覆盖模式同时清理原文与译文排版区域，两个区域可以不同。

对于只有整块文字框的 AI 结果，客户端在平坦底色上提取连通墨迹并按行／列合并，排除明显长画线和大轮廓，
得到更紧的擦字框与初始排版位置；普通细化保持 `textBox`，原文和译文保留。本地检测器已有的多行框直接保留。
大轮廓过滤仅用于包含多个文字的原文，避免把「回」等单字的外框误当气泡；分离的单像素点号也保留为擦字目标。
色差检测按 RGB 对比处理，避免亮度相同但颜色不同的文字被漏掉；填充仅从非前景像素取样，
不把邻近的独立黑边传播进已擦除文字。复杂纹理、墨迹过多或底色不可靠时保留给定锚点。
像素扫描有整页工作量上限，单个粗框超过 1 Mi 像素时跳过细化；这不是 OCR 或语义分割。

排版规划器先使用校准后的原文字号测量译文，能放下时保持原有区域，不为短译文自动扩大文本框。
放不下时才逐像素检查外侧留白。基础余量为原字号 80%、预览短边 8%，
限制在 2–48 预览像素内；长译文仍放不下时继续探测，最高为原字号 3 倍、预览短边 20%，且不超过 96 像素。
遇到背景色变化、图片边缘或其他文字的保留区域即停止；条带批量读取像素，避免每像素跨 JNI 调用。
已有移位的排版框保留。规划结束后检查框间重叠，按原文擦字锚点的上下／左右关系收缩相交排版框，
保留一个预览像素的间隔；不扩大排版框，也不改变原文、译文和擦字范围。原尺寸投影后再次检查重叠，
相同位置等无法可靠分离的锚点明确报错，并保留上次发布译图。留白探测和矩形避让仍不是完整的气泡实例分割。

竖向胶囊中的横排对白额外使用闭合背景恢复：从原文锚点附近搜索封闭、底色一致、端部收窄的背景连通区域，
只在与锚点对应明确且不包含另一个已知文字区域时接受。恢复该气泡内部的完整笔画范围，补齐偏移原文框之外的
上下行／左右字符；覆盖范围与译文排版位置分别测量。保留原本的横竖排方向，不根据气泡外形改成竖排。
译文以气泡主体中心为基准，取每行内部宽度的交集形成安全矩形，优先选择能容纳原字号的区域。
开口边界、邻近候选不明确、复杂底色、墨迹过密或超出扫描预算时保留原有处理，不扩大为整页覆盖。
单次搜索不超过 1 Mi 像素，整页背景搜索不超过 4 Mi 像素且受预览大小约束；不调用额外 OCR 或 AI。

`localGeometryVersion=6` 标记客户端已测量的局部几何和校准字号。气泡恢复可以修正有效 `textBox`，原 AI／检测器锚点另存
`recognitionBox`；原文和译文不变，服务端提供的此客户端字段不会被采纳。旧版本的分析缓存和已发布锚点在明确翻译／重排时，
使用原图本地升级，重新测量旧版本中可能偏大的字号；几何升级本身不调用 AI，且只在新译图完整生成后发布升级后的快照。
选择 AI 图片合成的翻译操作仍按对应路径调用图片服务，免 AI 的入口是本地擦字／覆盖模式下的「仅重新排版」。
普通读取仍显示最后成功译图；同版本重复重排复用几何，不会反复扩张。原始识别漏字不能靠此升级补全。
渲染身份为 `render-v8`，兼容收养 v1–v7 的旧发布结果；重排使用 `recompose-v7` 前缀，其身份还包含完整锚点 JSON 和几何版本。
默认 AI 分析身份保持兼容；端侧 OCR 分析加入 `source-geometry-v2`，显式翻译时应用新的识别与分组。服务端 JSON 中自称的局部几何版本会被忽略。

当前排版移植自 overlay-translator 的固定区域策略。对本地 OCR 的已知行框，采用行厚度中位数，
竖排还用总列长／非空白字符数限制注音和边距造成的高估；AI 粗框无行文字证据时保留像素投影／连通笔画估算作为回退。
`sourceFontSize` 在 v4 保存源行／字形厚度基准，按分析高度归一化，不再存储 v3 的目标字体 em。
旧版基准在显式翻译／重排时从原图重新测量，用户倍率保留。

源基准先乘用户倍率一次，再按实际目标字体度量构造约 0.35–1.6 倍的搜索范围，选择能完整放下的最大候选字号。
这采用了用户确认的 overlay 成熟策略，1.0 倍不再承诺和原文字形严格等大；短译文允许放大、长译文允许缩小。
绘制日志仅记录源基准、倍率、范围、最终字号和是否有可信掩膜，不记录原文或图片。
`MangaShapeTextLayout` 对可信气泡掩膜逐行／列检查完整矩形，内缩约字号 24%，并处理字素、换行及标点禁则；
矩形回退也复用同一个排版器和字号策略。没有完整可容纳结果时明确失败，保留上次成功译图。
本地擦字、覆盖及 AI 修复后程序排版使用该策略；整页／区域 AI 生成的最终文字仍由图片模型绘制。

横排按各行完整掩膜区间换行，保留英文词边界，不自动插入断词连字符；中日文的 OCR／译文换行归一化后重排，
其他脚本保留词间空格。竖排从右向左，在列容量内均衡字符分配，并检查行头／行尾禁则；
绘制按实际字形包围盒居中并裁剪到已测量的完整行列。方向判断按文字脚本而非 UTF-16 码元。
复杂标点的专用竖排字形和字体风格匹配尚未实现；从栅格图无法精确恢复原字体文件和排印点数。
局部坐标转换同时换算源字号、文字行和掩膜边界，掩膜栅格分辨率保留，避免 ROI 尺寸改变文字大小。
本地识别按文字行方向判断横竖排，不仅凭整段的长宽比把高段落判为竖排。
原文框严重错误、贴近画面的复杂描边、低对比网点和装饰字体仍可能残留或损伤画面，有限余量不是语义分割掩膜。

## 长图与生命周期

分析窗口与本地绘制块分别规划，复用已有 EXIF 校正的区域解码契约。长短边比例不超过 3 的普通页
整图识别翻译，原始分辨率高也不会因此拆分 AI 请求。分析预览采用采样区域解码，最长边不超过 3072，
总像素不超过 2 Mi；文字分析使用 JPEG 90 输入，坐标映射回原图。采样解码可能产生略大于预览的中间位图。

长条漫画先从有限预览中查找横向近白／近黑留白，日／中／韩／英文还用本地识别保护完整文字块；
在有限搜索范围内选择安全边界。辅助检测失败时仍可使用留白候选，因此这不是完美的分镜检测。
相邻分析窗口保留画面重叠和最近六条对白的文字上下文，按文字中心归属核心区避免重复输出。
这里的最近对白仅在同一张图片的分析分段间传递，下一张图片重新初始化；目前跨页持续保留的是本书术语，
尚未实现书级剧情记忆、统一 token 预算或缓存用量统计。后续公共方案见[AI 上下文与提示缓存](ai-context-management.md)。
若返回的自有文字触碰内部裁切边缘，明确失败，不能把残缺文字当成功结果。

程序先在原尺寸下排好每个完整文字区域，再将结果贴入约 3 Mi 像素以内的输出块；
一个对白跨越输出块时保持同一排版。单个文字区域超过该内存预算会报告失败。
PNG 按行流式编码，保留原始宽高，不创建整张长图位图。普通页的 AI 编辑只调用一次；
长条漫画按分析窗口编辑，不随本地输出块数量增加请求。图片编辑输入通过方形留白适配固定输出画布，
最终移除留白并恢复预览尺寸；非预期宽高比的返回结果被拒绝。区域模式仅贴回授权矩形。
已有最终译图仍可复用，强制重译后采用新分析策略；调整程序字号可复用分析和 AI 修复背景。

当前支持宽度不超过 8192、高度不超过 1000000 的可区域解码图片。图像生成模型在 1024 方形画布上处理，
其清晰度与文字保真度不等于原图。AI 定位不是像素级掩膜；复杂背景和边界不准确时，局部修复仍可能影响画面。
横竖排由区域信息及实际测量决定；无法在最低字号下容纳的译文报告失败，不静默截断。

翻译任务串行处理，取消、离开目的地或切书时拒绝发布迟到结果。ML Kit 的原生识别任务不能中断，
输入位图会保留到任务完成后再释放；失败自动页不会因普通状态刷新无限付费重试。

## 端侧 OCR 四边形与裁切（2026-10-28）

ML Kit 与 PP-OCRv5 保存每行原文四边形 `MangaSourceLine.quad`，与轴对齐紧框一起持久化。
四角按 TL/TR/BR/BL 排列并校验有限值、页面范围、凸性和顺序；旧缓存缺省为空，不用虚构四角补齐。
服务端响应仍不能声明这些本地字段，向图片编辑模型发送区域时仍移除本地识别元数据。

源字号优先从四边形边长计算，不再把斜行的外接矩形高度当作行厚度；没有四边形时维持旧矩形回退。
overlay 的 0.35–1.6 倍搜索策略和用户倍率语义不变。ROI 转换连续映射四角，并保持非正方形页与长图 band 的原始坐标关系。

PP-OCRv5 的识别裁切保留检测器 unclip 恢复的范围，并按源行厚度留边，遇到已检测邻行时收紧到间隙中点。
补边只影响识别输入，不改变原文紧框、擦除区域或字号基准。采用 A=-0.75 的 bicubic 透视采样直接生成高 48 的输入，
竖行旋转合并到对应角点变换中，取消中间图的双线性再缩放；图外采样复制边缘，不填入黑边。
全图与 ROI 使用同一坐标系解变换和量化，保证分块处理的像素一致。

无气泡归属的 Paddle 文字行按行距、字高、角度和方向建立邻接，再用最小生成树拆开异常长连接。
已确认的物理气泡分别处理；AI 整块原文和独立 ML Kit 块不跨原始身份合并。
阅读序先聚成行／列再排序，避免同一竖列的小幅横向框抖动颠倒上下片段。
这里没有接入完整的跨泡语义 Flow、旋转译文绘制、NCNN 或 AOT-GAN，也没有改变模型会话生命周期与章任务队列。

已有成功译图继续保留。「仅重新排版」可重算已有四边形的字号，但不会补跑 OCR 或重新分配译文。
要将新裁切、四边形和分组应用到缺少这些数据的已译页，应重新翻译。

## NO_FIT 排版恢复（2026-10-28）

修复默认 100% 倍率也会发生的三类拒绝：

- 超长 ASCII 单词放不下一整行时，旧断词回退会不断退到一个字母，导致明明可以多字母换行却报 NO_FIT。
  现在优先词边界；确实需要拆词时，使用当前行能容纳的最远字素边界，同时保留标点禁则。
- 行尾禁则只限制人为换行处；原始对白片段末尾的左引号／左括号可以保留，不因为它无法与下一段合并就拒绝整段。
- 常规字号仍先按 overlay 的 0.35–1.6 倍区间搜索。全段放不下时，再向下搜索至 8px；原本最低字号已小于 8px 的区域保持原有下限。
  仅缩字，不扩大排版区域、不忽略掩膜、不截断文字。日志标记 `shrinkFallback`，没有更改字号倍率设置。

空白区域规划与最终绘制使用同一套字宽、行高、描边、断词和禁则测量；矩形区域走无掩膜分配的快速路径，
真实的空掩膜仍明确失败，不退回矩形覆盖。
几何版本升级到 v6；新渲染／重排身份防止复用旧排版结果。旧分析文本与最后成功译图保留。
有效分析缓存仍在时，失败页点「翻译当前页」可重试本地合成；不需要强制重新翻译。
已成功页可用「仅重新排版当前页」应用本次修正，均不因排版失败自动重复付费请求。

确实过长或区域不足时仍拒绝发布，保留最后成功译图；面板错误包含文本区域序号和原因码，并提供本地化提示。

## WebP 奇数裁剪边界

2268×3154 页面在内存预算下分为 1131／1131／892 行。PLK110 上原生 WebP 解码器
会把奇数裁剪起点向偶数像素扩展：请求第 1131..2262 行，实际返回 1132 行，导致最终
PNG 拼接超过总高度并触发原先无说明的 `Failed requirement`。这与源语言、AI 排版内容
和擦字引擎无关；普通 PNG 在相同回归中没有扩展。

`MangaAndroidRegionDecoder` 对全分辨率请求先在原始图片坐标系把左／上起点对齐偶数，
再精确裁回请求范围，最后执行 EXIF 变换。不通过缩放消化多出的像素；额外分配最多
一行、一列的解码上下文。带采样的预览／阅读请求保持现有采样规则。
输入区域与原生返回尺寸、PNG 输出分块校验现在附带尺寸和已写入行数，便于追踪异常。

回归包含 SDK 26／35 下八种 EXIF 方向的完整像素比较，以及真机上同尺寸 PNG、无损
WebP、有损 WebP 的奇数分段、奇数左上角裁剪和完整 PNG 编码。渲染版本提升至 16、
本地重排版本提升至 15；识图缓存不变，已有发布译图继续保留。

验证：295 项定向单元测试（36 类）通过，包括 SDK 26／35 的解码适配与 EXIF 契约；
PLK110 的 3 项原生测试通过，覆盖上述 PNG／无损 WebP／有损 WebP 分段与完整输出、
读取最终 PNG 和既有本地识字回归。Debug 与测试 APK 已安装。测试使用合成色条图，
不调用翻译 AI；用于排查的缓存副本与路径清单已删除，原图和真实书籍数据未修改。
