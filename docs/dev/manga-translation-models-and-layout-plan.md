# 漫画翻译：模型选型与气泡排版改进方案

日期：2026-10-28

状态：选型已确认，模型已开始初版接入；轮廓逐行排版、竖排与分阶段缓存已实现，真机验收尚未完成。具体实施范围与阻塞见第 11、12 节。

## 1. 目标与范围

在 Legado with MD3 现有漫画翻译流程中，提高文字检测、去字掩膜、复杂气泡识别与背景修复质量，解决译文被限制在 OCR 原文矩形内而字号过小的问题。

- 目标设备：骁龙 8 Gen 2、12GB 内存；12GB 为整机内存，不是应用可用预算。
- 图片处理优先在本地完成；保留现有离线／AI 文字翻译路径。
- CTD、MangaLens YOLO11n-seg、漫画版 AOT 的模型权重均不内置于 APK／AAB，提供下载、本地导入和删除功能；避免引入多套图像推理运行时。
- 沿用当前阅读器、图片获取、区域解码、长图输出与 MD3 交互。
- 本次范围为设计文档，不包含模型下载、转换、代码修改或性能承诺。

现有实现与运行限制见 [漫画翻译当前实现](manga-translation.md)。该文档描述现状，本文描述后续设计；不能把本文方案当作已完成能力。

## 2. 已确认的模型选型

| 环节 | 选定模型／实现 | 职责 | 接入状态 |
| --- | --- | --- | --- |
| 文字检测 | Comic Text Detector（CTD） | 文本块、文字行定位 | 待接入 |
| 文字掩膜 | CTD 分割输出＋本地细化 | 提取文字像素，生成最终擦除掩膜 | 与检测共用模型，待接入 |
| 复杂气泡识别 | MangaLens YOLO11n-seg | 每个气泡的边界框与实例掩膜 | 待接入 |
| 复杂背景修复 | manga-image-translator 漫画版 AOTGenerator | 补全擦除文字后的局部背景 | 待导出与验证 |
| OCR | 暂时沿用现有 ML Kit | 将文字图像转换为原文 | 本轮不更换 |
| 翻译 | 现有离线／AI 引擎 | 生成译文 | 本轮不重新选型 |
| 排版与嵌字 | 本地字体测量与轮廓约束算法 | 换行、字号、位置和绘制 | 已实现轮廓横竖排，见第 12 节；仍需样本验收 |

三个模型分别解决文字位置、气泡空间和背景补全，不能相互替代。导入模型指接入权重及对应前后处理，不是将 Python／桌面项目整体搬入 Android。

### 2.1 CTD：文字检测和掩膜共用一套模型

来源：[dmMaze/comic-text-detector](https://github.com/dmMaze/comic-text-detector)。作者说明其输出包含文本框、文字行及文字分割，用于漫画识别、去字和嵌字。

优先以 manga-image-translator 使用的 `comictextdetector.pt.onnx` 建立基线。上游权重来源及哈希映射见 [CTD 接入源码](https://github.com/zyddnys/manga-image-translator/blob/main/manga_translator/detection/ctd.py)。公开的一个 [CTD ONNX 分发文件](https://huggingface.co/mayocream/comic-text-detector-onnx/tree/main)约 94.7MB，仅作为存储规模参考；正式制品须核对来源与等价性。

处理路径：

```text
局部图片／重叠图块 → CTD
                    ├─ 文本块与文字行 → OCR、阅读顺序
                    └─ 分割结果 → 原图局部细化 → 最终文字掩膜
```

模型输出不是可以直接使用的最终擦除范围。后处理需要：

1. 正确还原缩放、补边和图块偏移，映射到统一页面坐标。
2. 关联 OCR 文字与检测区域，处理跨图块重复检测。
3. 在局部高分辨率图像上补全小字、描边和抗锯齿边缘。
4. 根据笔画尺度控制膨胀，并保护气泡边框及分镜线。
5. 检查覆盖不足、异常面积和文字与线稿粘连；不确定区域进入待处理状态。

参考 [上游掩膜细化流程](https://github.com/zyddnys/manga-image-translator/blob/main/manga_translator/mask_refinement/__init__.py)，但需独立适配 Android。CTD 减少对颜色阈值的依赖，不意味着可以取消质量检查。

### 2.2 MangaLens YOLO11n-seg：气泡实例分割

来源：[huyvux3005/manga109-segmentation-bubble](https://huggingface.co/huyvux3005/manga109-segmentation-bubble)。模型卡将其描述为基于 YOLO11n 的漫画气泡实例分割模型，输出气泡框及独立掩膜。

已有社区提供 [1024 输入的 ONNX 导出](https://huggingface.co/mednasserallah/manga109-segmentation-bubble-onnx/tree/main)，文件约 11.8MB。可用于快速验证接口；正式接入须与原权重结果对照，记录可复现的导出过程。

本地后处理包括：

- 将文字块关联到具体气泡，支持一个气泡包含多个 OCR 块。
- 对轮廓保留安全边距，去除尾巴、尖角和过窄部分。
- 检查相邻气泡误合并、开放气泡泄漏及跨分镜关联。
- 区分旁白框、气泡外拟声词，不能强行归入最近气泡。
- 对彩漫、韩文条漫、无边框对白和重叠气泡单独验收。

模型卡上的精度和速度属于作者报告，不能当作目标手机实测结果。分割结果提供可排版空间，字号和换行仍由本地算法决定。

### 2.3 漫画版 AOT：复杂背景修复

选定 [manga-image-translator 的 AOTGenerator](https://github.com/zyddnys/manga-image-translator/blob/main/manga_translator/inpainting/inpainting_aot.py)及其 `inpainting.ckpt`，不混用其他同名 AOT 权重。

该模型的一个 [SafeTensors 转换版本](https://huggingface.co/mayocream/aot-inpainting)标示约 568 万参数，[FP32 权重文件](https://huggingface.co/mayocream/aot-inpainting/tree/main)约 22.7MB。此信息仅用于评估权重规模；SafeTensors 不能直接交给 ONNX Runtime 执行，仍需导出、适配和验证。

建议从 512×512 局部裁剪开始测试，裁剪应包含周围背景上下文。输入尺寸是验证起点，不是已经确定的质量或性能最佳值。

| 背景类型 | 处理方式 |
| --- | --- |
| 纯白、纯黑、纯色气泡 | 可靠背景采样＋掩膜内填充 |
| 平滑渐变 | 局部颜色拟合／传统修复 |
| 网点、纹理、插画背景 | AOT 局部修复，检查残字、接缝和线稿变化 |
| 无法可靠修复 | 保留原文，允许查看译文与局部重试 |

模型可以读取掩膜外上下文，但最终只在批准修改的范围内合成。模型估计的背景不等于恢复被遮挡的真实原画。

LaMa／Big-LaMa 仅保留为后续质量对照，不纳入本次确定的默认模型。只有 AOT 的真实样本效果不足，且替代模型的质量收益能覆盖设备成本时，再另行评估。

## 3. 当前精细掩膜失败的背景

当前 `MangaTextInpainter` 在 OCR 元素周围外扩固定 3px，以边缘主色估计背景，用固定色差阈值 36 生成候选像素，再排除触及局部边界或面积过大的连通分量，最后膨胀 1px 并插值修复。

这种方法在干净纯色背景上较容易工作，在贴边文字、描边字、渐变、网点与低清图上可能拒绝处理。当前还要求所有 OCR 元素都找到合格分量，否则整页失败；反过来，一个元素找到一个分量也不代表所有字都被覆盖。

CTD 接入后，应将判断改为区域级质量评估，输出具体原因和局部状态，避免一个区域失败导致整页无法翻译。不能单纯放宽阈值或删除检查。

## 4. OCR 原文矩形内字号变小的原因

### 4.1 当前计算逻辑

分析依据为 `MangaTranslationRepository.renderPatch` 和 `MangaTranslationRegions`，整理时的现状如下：

```text
排版范围 = OCR 原文矩形
初始字号 = clamp(原文矩形高度 / 2, 10, 48)
排版方式 = 横排、固定宽度、居中

若排版总高度超出原文矩形：
    字号每次减 1，直到约 8 图像像素
若仍放不下：
    报告排版失败
```

这里的字号是图像像素，不是 Android 界面的 sp。当前代码没有从较小初始字号向上寻找更合适字号的步骤。

### 4.2 已确认的结构性问题

| 原因 | 影响 |
| --- | --- |
| OCR 原文矩形被当作译文可用空间 | 气泡周围空白无法利用，译文被挤在小区域里 |
| 原文竖排，译文统一横排 | 窄长矩形导致每行字数很少，频繁换行后被迫缩字 |
| 初始字号为矩形高度的一半 | 单行原文也可能从偏小字号开始，且不会自动向上搜索 |
| 初始字号统一封顶 48px | 大字、喊话和高分辨率大气泡不能保持字号层次 |
| 只检查是否放得下 | 缺少可读性下限，极小字也可能成为成功结果 |
| 各 OCR 区域独立排版 | 同一气泡被拆块时，各块可能字号不一致 |
| 补丁外扩没有进入文本布局范围 | `patchBounds` 外扩 8px，但 `textBounds` 仍是原文矩形 |

其中，有些小字在初始字号设置时就已产生，并不是缩小循环造成的。

### 4.3 需要结合实际样本确认的因素

- 译文变长：同一语义翻译后需要更多字符或行数。
- 换行被保留：当前将 OCR 行用换行符连接；若译文保留视觉换行，可能产生不必要的短行。
- 气泡文本未归并：现有合并主要处理跨图块重复行，不等于按气泡组织完整对白。
- 显示缩放：文字画入译图后随图片一起缩放。若 1536px 宽译图显示为 384 个逻辑单位宽，8px 名义字号约显示为 2 个逻辑单位；实际字形大小还受字体影响。

以上说明可能机制，不代表已复现每一种样本。单独提高最低字号只会让部分区域从“小字成功”变成“排版失败”，不足以解决根因。

## 5. 气泡内排版与嵌字解决方案

### 5.1 分离擦除范围和排版空间

| 数据 | 含义 | 使用边界 |
| --- | --- | --- |
| `textMask` | 原文字形、描边和抗锯齿像素 | 控制擦除与修复 |
| `bubbleMask` | 气泡实例区域 | 确定文本归属和空间 |
| `protectMask` | 高置信度边框、分镜线及受保护线稿 | 约束修复和膨胀 |
| `layoutArea` | 气泡内部扣除边距、尾巴、狭窄部分后的区域 | 约束译文位置 |

CTD 生成文字候选，MangaLens 生成气泡候选，本地后处理产生最终区域。气泡大不代表可以整块涂白；原文窄也不代表译文只能在同一窄框内排版。

文字补丁画布必须扩展到实际布局范围，否则新布局会被旧补丁边界裁切。修复层仍受文字掩膜约束，两者分别缓存和合成。

气泡识别失败时回退保守区域；无法在可读字号内排入则保留原文，不任意扩框到未知背景。

### 5.2 按气泡归并文本

1. 通过重叠、包含关系、方向和位置将 OCR 块关联到气泡。
2. 同一气泡中的多列文字按阅读顺序组织，保留真实段落。
3. 区分主体文字、注音和小标点，避免重复翻译和错误字号估计。
4. 区分语义段落换行与 OCR 视觉换行；后者允许重新排版。
5. 不只按距离合并，避免将邻近气泡、旁白或拟声词串在一起。

一个气泡可以有多个段落，但应统一协调字号与空间。修复和排版均通过后才替换整个气泡，避免原文已擦除而译文未能嵌入。

### 5.3 建立目标字号与可读性约束

目标字号综合以下信息估计：

- 横排文字的典型行高、竖排文字的典型列宽。
- 去除注音、小标点和异常框后的稳健统计。
- 气泡大小、对白／旁白／喊话类型。
- 输出尺寸、参考阅读显示宽度和用户字号偏好。

在目标字号附近搜索布局，允许空间充足时放大，也允许有限缩小。取消固定 48px 作为所有场景的统一上限，但保留合理的样式和资源边界。

最低可读字号与参考显示尺度关联，不能仅写死为 8px、12px 或 16px。采用稳定参考尺度生成缓存，避免旋转或缩放引发反复重渲染；实际显示过小时提供局部放大或译文面板。

同一气泡字号保持一致；页面普通对白尽量协调，同时保留喊话、耳语等有意义的差异。

### 5.4 根据气泡轮廓优化换行

椭圆、不规则气泡不能只用单一固定宽度矩形描述。建议流程：

1. 枚举有限数量的字号、行数和整体位置候选。
2. 对每一行完整字形高度（含描边）计算都可用的水平区间。
3. 按实际字体测量宽度，以动态规划选择换行点。
4. 优先保证不越界、译文完整和可读字号，再比较断句、孤行、行宽平衡及位置。
5. 对最终字形边界进行检查，不能通过画布裁切掩盖溢出。

中文使用标点禁则，避免句号、逗号出现在行首及左括号落在行尾，尽量不拆数字与单位；英文优先按单词换行。首版使用轻量规则，不为断句额外引入大型模型。

字号与换行的关系存在离散变化，应比较多个候选布局，不仅依赖单次“不断减字号”的循环。限制候选数量和计算预算，保证长页任务可取消。

### 5.5 横竖排策略

- 中文默认横排，但使用整个可靠气泡区域。
- 非常窄长的气泡比较竖排候选，并允许用户手动切换。
- 根据目标语言和气泡形状选择，不统一强制横排，也不机械复制原文方向。
- 竖排需要处理标点方向、字形旋转和短数字横排，不能简单逐字换行。
- 字体回退后重新测量；描边、阴影和旋转占用必须计入边界。

### 5.6 放不下时的处理顺序

```text
利用可靠气泡内部空间
    → 优化换行、行数、位置与行距
    → 比较适合的横排／竖排布局
    → 在可读范围内调整字号
    → 仍无解：保留原文并提供完整译文查看
```

允许用户修改区域、方向、字号或译文。可提供主动选择的“精简译文”，保留原译文，不自动删句、截断或过度压扁字形。

## 6. 管线、缓存与失败隔离

```text
原图与统一坐标
    → CTD 文字检测、分割与 OCR
    → MangaLens 气泡识别、文字归属与阅读顺序
    → 文字掩膜细化／质量检查
    → 按背景选择基础修复或 AOT
    → 译文与气泡轮廓共同驱动排版
    → 区域检查
    → 原图＋修复层＋文字层合成
```

翻译可在区域语义组织完成后独立执行，不必等待修复结束。各阶段保存中间结果：改译文只重排版；改字体只重新测量与绘制；改掩膜只重新修复并合成。

- 图片内容、采样／坐标策略、模型及后处理版本参与检测和修复缓存标识。
- 原文、语言、引擎、提示词及影响结果的上下文参与翻译缓存标识。
- 译文、字体、字号策略、气泡轮廓和排版版本参与布局缓存标识。
- 每个区域保存成功／待处理及具体原因，支持部分译图。
- 页面解码或写入失败仍是页面级错误；取消必须正常传播，不能转成局部失败。
- 保留原图，保证翻页、切换配置及重试后的旧任务结果不会覆盖当前状态。

现已让每个区域补丁计算一次，跨条带复用临时 PNG，写过后释放；持久中间结果使用独立配额的分阶段缓存，见第 12 节。

## 7. Android 部署与模型管理

### 7.1 分发原则

CTD、MangaLens YOLO11n-seg 和漫画版 AOT 的权重均不随 APK／AAB 打包，也不在首次启动时自动下载。用户通过模型管理入口主动下载或导入；安装完成并通过校验后，本地推理不再需要网络。

安装包仅包含功能代码、必要的推理运行时、模型描述与前后处理逻辑。此约定针对本次选定的三个图像模型，不改变现有 ML Kit OCR 和翻译语言包的 SDK 管理方式。

新增图像推理优先统一使用 ONNX Runtime Android，先建立 CPU／XNNPACK 基线，再比较硬件加速。是否受益取决于模型算子、执行分区和实际设备，不能因设备具有 NPU 就承诺模型能完整加速。[官方移动端部署说明](https://onnxruntime.ai/docs/tutorials/mobile/)

| 模型管理项 | 内容 | 使用时机 |
| --- | --- | --- |
| 文字检测包 | CTD，检测与掩膜共用 | 模型增强检测 |
| 气泡排版包 | MangaLens 分割模型 | 气泡内自动排版 |
| 背景修复包 | 导出验证后的漫画版 AOT | 复杂背景修复 |

上述公开参考文件约合 129MB，但包含不同格式和分发来源，仅用于存储量级估算，不是最终模型包大小、运行内存或 APK 增量。OCR、翻译语言包和推理运行时另计。

### 7.2 下载、本地导入与删除

三个模型分别管理，均提供以下功能：

| 功能 | 实现要求 |
| --- | --- |
| 下载 | 展示模型用途、版本、来源、下载大小与所需存储；用户主动开始，提供进度、取消和失败重试；来源支持时提供断点续传 |
| 本地导入 | 通过系统文件选择器选择受支持的模型文件或模型包，复制到应用管理目录，完全离线完成校验与安装 |
| 删除 | 展示将释放的空间，取消相关下载／排队任务，协调在途推理结束并释放模型会话后，删除应用管理的权重及关联安装临时文件 |

下载与导入使用同一套安装流程：写入临时位置 → 校验大小、SHA-256、模型身份及格式 → 验证输入输出契约与运行时兼容性 → 原子安装 → 更新可用状态。失败时清理临时文件，保留此前可用版本；不得让半成品成为可用模型。

本地导入仅支持应用明确兼容的制品，不能把任意 `.onnx` 文件视为可用模型。原始 `.pt`、`.ckpt`、SafeTensors 等未经适配的训练／转换权重不作为手机直接导入格式；应提示需要对应的部署版本。模型包如包含外部张量数据，必须完整校验，解包路径限定在安装目录内。

模型文件存放在应用持久文件目录，与可被系统淘汰的译图缓存分开。删除仅作用于应用管理的副本，不删除用户用于导入的原始文件。

删除时先阻止该模型的新任务，并使依赖该模型的旧任务结果失效。不能中断的原生推理须在安全结束、释放资源后再删除文件；界面在完成前显示“正在删除”。删除后立即更新能力状态，后续使用时提示下载或导入，不自动重新下载。

### 7.3 模型状态、能力与缓存

沿用现有 MD3 组件，在漫画翻译设置中提供模型管理入口。每项展示版本、来源、实际占用和状态，并提供相应操作：

- 未安装：下载、导入。
- 下载中／导入中／校验中：进度与可取消操作。
- 可用：删除，以及可用时的更新入口。
- 下载失败／校验失败／不兼容：具体原因、重试下载或重新导入。
- 正在删除：完成前不允许再次加载同一模型。

模型缺失时明确说明受影响的能力：CTD 缺失时无法运行模型检测与掩膜；MangaLens 缺失时无法运行模型气泡分割；AOT 缺失时无法运行增强背景修复。保留可用的基础路径并标明当前模式，不把传统算法伪装成模型推理，也不静默触发下载。

删除模型默认保留已生成的译图和可复用中间结果，用户仍可查看既有结果；重新计算受影响阶段需要重新安装模型。模型版本、内容哈希及前后处理版本参与缓存匹配，不能将不同模型生成的结果误当作同一版本复用。译图缓存清理与模型删除为独立操作，界面分别展示占用。

### 7.4 运行与制品要求

模型确定后再按实际算子裁剪运行时；量化需要有真实样本的精度和速度证据，不假定必然更快。

长图分块处理，保留足够上下文并统一坐标；重型图像任务串行执行，按实际内存预算装卸模型。预处理下一页不能挤占当前阅读任务。

实施前需要补齐以下制品清单：

- 原始仓库 revision、权重文件名、下载地址、SHA-256。
- 权重来源及适用的再分发条款，不仅依赖第三方转换仓库标签。
- 导出脚本、工具版本、opset、输入尺寸、布局、归一化和掩膜语义。
- 输出解析、补边／缩放还原、阈值、NMS 及分割后处理版本。
- 原框架与 ONNX 的数值和视觉一致性验证。
- Android 算子支持、实际执行后端、耗时、峰值内存和温升。

这些信息尚未锁定，本文不能直接替代可发布的模型 manifest。

## 9. 验收与当前验证边界

样本至少覆盖日文竖排和注音、英文对白、韩文彩色条漫、黑底白字、渐变网点、描边字、贴边文字、拟声词、开放／重叠气泡、低清图和跨条带气泡。

| 维度 | 验收要求 |
| --- | --- |
| 检测与掩膜 | 记录漏检、残字和误擦；检查边框与线稿保护，不能只判断掩膜非空 |
| 气泡识别 | 文字归属正确，轮廓不泄漏到邻泡或分镜，排版区避开尾巴和边框 |
| 排版 | 译文完整、不越界、不被裁切；正常阅读比例可读；同泡字号一致 |
| 修复 | 与同一解码基准比较，修复层掩膜外像素不变；人工检查纹理和线稿 |
| 失败恢复 | 部分成功明确提示，待处理区域保持原文，局部重试不重做全部阶段 |
| 生命周期 | 无文字、取消、快速翻页、切换配置、原图切换和模型不可用均有正确结果 |
| 模型分发 | 检查 APK／AAB 不包含三个模型的权重，首次启动不自动下载；未安装时提供下载与导入入口 |
| 模型安装 | 覆盖下载、离线导入、取消、断网、空间不足、文件损坏及格式不兼容；安装失败不覆盖原有可用版本 |
| 模型删除 | 覆盖空闲／推理中／下载中删除，确认资源释放、文件清理及能力状态更新；不删除导入源文件，不自动重新下载 |
| 模型与缓存 | 删除模型后已有译图可查看；清理译图缓存不删除模型；不同模型版本和哈希的缓存不会误复用 |
| 性能 | 记录冷／热耗时、各阶段峰值内存、连续阅读温升和 Release 体积增量 |

验收应比较改进前后同一批样本的可读字号比例和人工质量评价，不只统计“未报错”。具体质量阈值和性能预算在基线测量后确定，不虚构实测数值。

本文整理了源码分析、已确认选型和后续方案。尚未执行模型下载、ONNX 转换、真实图片推理、Android 真机性能或功能验证。

## 12. 轮廓排版、竖排与分阶段缓存（2026-10-28）

本节更新第 11 节的排版与缓存状态，其余模型和真机验证限制继续有效。

### 12.1 轮廓逐行／逐列排版

- `MangaLayoutArea` 从气泡实例掩膜建立连续行／列区间；每个布局带对完整字形高度／宽度及安全边距求交，避开孔洞、边框与细尾，不再统一裁成一个内部矩形。
- 根据轮廓面积重心、字号、行列数和有限位置候选搜索；动态规划选择换行，比较空白比例与孤行代价。保留硬换行、段落、完整单词、字素簇及数字／单位组合，执行中英文行首／行尾标点禁则。
- 横排仍使用系统字体塑形；API 28 起启用 fallback line spacing，按实际字体和字形边界重新测量。最后在有外侧保护带的透明层绘制，逐像素检查实际墨迹，不使用画布裁切掩盖越界。
- 保留稳定参考尺度与可读下限。上限为 33 个字号、64 行／列、1024 个排版单元、8192 个 UTF-16 单元、120000 次断点搜索；单区域宽高最多 4096px。超过预算、无法排入或实际墨迹越界时保留原文并提供完整译文，取消正常传播。

### 12.2 竖排与方向设置

- 翻译面板新增自动／横排／竖排，经 `MangaSettingsGateway.update { copy(...) }` 保存。方向变化取消旧任务、更新请求身份；旧任务不能覆盖新配置。
- 自动模式默认横排，对窄长中日韩气泡比较竖排；强制方向遵循用户选择。竖排从右向左分列、列内从上向下。
- 基于 Unicode Vertical_Orientation 决定直立、变体与顺时针旋转；竖排标点使用可用的字形变体，字体不支持时按方向回退。连续拉丁词等以完整塑形文字运行旋转，不逐字拆散；1–2 位短数字采用列内横排，并保持与该气泡一致的名义字号。
- ICU 字素边界保护代理对、组合重音、变体选择符和 Emoji ZWJ 序列。API 29 起使用系统 ICU 竖排属性；26–28 使用 Unicode 17.0.0 的 U/Tu 紧凑范围表。生成器锁定源 SHA-256，随应用保留 Unicode V3 许可。字体缺字与漫画实际阅读效果仍需设备样本验收。

### 12.3 持久分阶段缓存

| 缓存阶段 | 标识中的主要依赖 | 可复用场景 |
| --- | --- | --- |
| OCR 检测／识别 | 原图内容、解码／采样、原文语言、CTD 与 OCR／分块版本 | 改方向、字号、目标语言、引擎或译文 |
| 气泡实例 | 原图内容、采样、气泡模型与解析版本 | 改译文、方向、字号或文字翻译引擎 |
| 翻译 | 有序原文列表、语言、引擎、模型、提示词与有效参数 | 改字体、方向、排版轮廓或修复方式；整批上下文参与标识 |
| CTD 原始文字掩膜 | 原图局部内容／坐标、CTD 与处理版本 | 调整 OCR 文字、译文或排版 |
| 修复透明层 | 原图、文字几何与裁剪、CTD／AOT 及细化修复版本 | 改 OCR 错字但保持几何、改译文、方向或字号 |
| 布局计划 | 译文、语言、完整轮廓、字号／方向策略、字体测量与系统版本 | 相同配置再次合成；不会误复用其他轮廓或字体的布局 |

`MangaStageKeys` 集中维护这些依赖；区域 ID 基于原图和文字几何，修正 OCR 文本不改变 ID。请求支持按区域 ID 覆盖译文，排版／修复各自复用；区域编辑器仍属于后续工作。

中间结果存入 `cacheDir/manga-translation-stages-v1`，使用长度分隔的 SHA-256 键、内容校验和、原子写入及 LRU 淘汰。单条最多 32 MiB、总计最多 64 MiB；空间不足时跳过可选缓存，损坏时重算，失败结果不作为成功缓存。取消或模型代次变化不得发布半成品／错误模型身份的中间结果。

最终译图位于 `manga-translation-v3`，沿用独立 128 MiB 配额，包含输出临时文件和条带补丁；因此两类缓存持久占用上限合计 192 MiB。清理译图缓存同时清理全部中间结果，删除模型不删除这些缓存或既有译图。系统仍可能回收缓存，它不能替代原图。

含待处理区域的最终译图不短路重试：重新请求时复用有效阶段，重算失败阶段，再流式合成。模型版本或轮廓变化仅使受影响的阶段失效。尚未提供掩膜／区域编辑器与独立区域重试按钮。
