# AI 上下文与提示缓存方案

> 状态：设计提案，2026-10-30。本文记录源码审查和官方接口核对结果；以下新增模型、策略与阶段均未实现。
> 本轮不修改运行逻辑、不调用付费模型、不创建 Gradle 模块。实施时按垂直切片验证。

## 目标

让聊天、小说翻译、漫画翻译和书籍分析共用预算、稳定请求结构和用量统计，同时保留各业务自己的记忆语义。
衡量成功的指标是同等质量下的实际输入费用、首字等待与完整任务耗时，而非单独追求缓存命中率。

需要区分三件事：本地结果缓存命中可以不发送请求；提示缓存复用输入计算，仍占模型上下文；
书籍记忆是应用持久保存的语义资料，供应商缓存过期后仍须存在。设置会话 ID 不等于获得服务端永久记忆。

## 供应商缓存差异

以下是官方服务规则；第三方转发采用相同协议，不代表支持相同缓存参数、价格或统计。
接口、模型、最低长度和保留时间在实施时重新核对；不在公共层硬编码一组通用阈值。

| 服务 | 请求组织与适配方向 | 用量读取 |
| --- | --- | --- |
| DeepSeek 官方 Chat | 自动前缀缓存，无需额外开关。前缀必须已持久化为可匹配单元；公共前缀的建立可能需要多次请求，不保证第二次就命中。固定规则/书级快照和动态页面分开，保持消息边界稳定 | `prompt_cache_hit_tokens`、`prompt_cache_miss_tokens`；`prompt_tokens_details.cached_tokens` 与命中字段是同一计数，不能重复累加 |
| OpenAI 官方 | 当前官方文档区分模型代际。部分模型隐式缓存，较新模型的 Responses 支持显式边界和写入生命周期；稳定内容后设置边界可以避免缓存一次性的页面。`prompt_cache_key`、旧版 retention、新版 options 不可混用或发给所有兼容服务 | 输入明细中的缓存读取及适用模型的缓存写入、各生命周期写入量；Chat/Responses 分别解析自身 schema |
| Anthropic 官方 Messages | 支持顶层自动 `cache_control` 或块级显式边界。漫画/翻译的动态后缀适合把边界明确放在稳定块结尾；聊天的追加历史可使用自动边界。写入与读取分别计价，生命周期和最低长度依模型/平台而定 | `cache_read_input_tokens`、`cache_creation_input_tokens`、普通 `input_tokens`；总输入是三者之和 |
| Gemini | 官方文本 API 有隐式缓存；部分接口/模型另有不同缓存机制。当前项目的 Gemini 接入是图像服务，不能宣称已支持原生 Gemini 文本缓存 | 留给实际原生文本适配器，不能套用 OpenAI 统计字段 |
| 自定义/兼容服务 | 默认只优化消息结构，不附加未知字段；能力明确后再启用原生参数 | 缺失统计标记为未知，不能显示成未命中或零消耗 |

依据：[DeepSeek 缓存](https://api-docs.deepseek.com/guides/kv_cache)、
[DeepSeek Chat API](https://api-docs.deepseek.com/api/create-chat-completion)、
[OpenAI 官方提示缓存文档](https://developers.openai.com/api/docs/guides/prompt-caching)、
[Anthropic 提示缓存](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)、
[Gemini 缓存](https://ai.google.dev/gemini-api/docs/caching)。

## 请求结构：稳定前缀和动态后缀

按变化频率组织内容，保留角色与信任边界：

```text
固定指令、输出契约、固定工具 schema
本书/会话稳定记忆快照                ← 稳定边界
当前批次或场景的记忆增量
需要保留的完整近期对话/工具轮次
当前阅读位置、相关词条、纠错要求
本次正文、页面图片、区域与 frame 数据
```

这是业务上的顺序，实际编码由协议适配器决定；例如 Anthropic 的 tools/system/messages 有自身层级。
用户资料、OCR 结果、书籍原文和记忆值始终是数据，不能为了缓存而提升为可执行的 system 指令。
保留固定的解释/隔离规则，动态数据使用明确的数据块或 user 消息。

需要做的具体调整：

1. 聊天不再把阅读位置混入固定 system 中段；同一会话的固定规则和记忆快照独立。
2. 工具增强入口先保留稳定任务规则，再提供动态书籍上下文；工具定义顺序和 schema 序列化稳定。
3. 小说把固定翻译契约、稳定核心术语与每片段相关词条、重试说明分开。保留现有词典匹配能力。
4. 漫画把 frame、锚点、近期对白和图片放在后部，固定排版契约不随页变化；不回传旧页坐标和排版 JSON。
5. 不在前缀放时间戳、随机请求 ID、阅读进度和随页变化的全部状态。请求身份存在本地元数据里。
6. 稳定资料在创建快照时排序并规范序列化；快照内字节和消息/块边界保持不变。后续新资料先作为后部增量，
   不每新增一条就重新排序并改写整个前缀。修正错误与人工修改必须立即生效，允许为正确性重建快照。

不要为达到缓存最低长度填充废话、整本书或无关工具，也不要为提高命中率保留已失效事实。
图库图片只有在实际内容及编码、尺寸等条件一致时才可能复用；同一本漫画不同页面不会因为相同书籍 ID 而共享图片 token 缓存。

## 共享边界

先在现有 `:app` 内形成少量有真实调用方的规则，不新增模块或通用基础框架。
下列是建议职责名称，不是已存在 API，也不要求每个职责都建一个接口：

| 职责 | 所有者与边界 |
| --- | --- |
| 上下文块/计划 | `domain/model/ai` 的值模型：内容、角色、来源、必需性、顺序、稳定修订、可缓存边界。没有 Android/File/Room 类型 |
| 预算和选择 | `domain/usecase` 的纯规则：输入块、模型容量和输出预留，返回组装计划及裁剪原因；不读取数据库，不执行网络 |
| 业务记忆 | 现有业务 Repository 持有。聊天、翻译、配音各自提供快照；不要把所有资料塞入 `AiMemory` 的 conversationId 字段 |
| 供应商缓存能力 | `data/repository/ai` 按服务端、接口和模型明确适配；不依赖用户展示名称包含某个单词就启用未知参数 |
| 用量 | 共享请求/响应模型 + 各 Handler 解析；流式和非流式使用同一语义，所有入口可消费 |
| UI | 展示简短用量与上下文状态，经既有 Gateway/UseCase 读取；不直连网络或 DAO |

已有 `sessionId` 继续表示网关会话路由。语义记忆 scope、提示缓存 key、结果缓存 key 和每次请求 ID 分开建模。
语义 scope 由账号/本地配置、本书、任务族、源语言、目标语言确定；切换模型可继续使用已验证的语义资料，
但编译后的请求与服务端缓存身份必须区分供应商、协议、模型和模板版本。
缓存 key 使用稳定的不透明摘要，不包含明文书籍 URL、密钥或完整提示；不每页重建随机 key。
缓存 key 相同也不能跨过前缀内容差异，不作为访问控制或内容一致性证明。

## 预算与压缩

```text
可用输入 = 模型上下文上限 - 输出/思考预留 - 安全余量
输入估算 = 指令 + 工具 schema + 记忆 + 历史 + 工具结果 + 本次文本/图片
```

准确 tokenizer 或官方计数可用时使用；否则采用模型/语言相关的保守估算并标记为估算。
中文、日文、代码和图片不能统一按字符除以 4；base64 字符数也不是图片 token 数。
模型容量未配置时使用可说明的任务预算，不视作无限。保留当前用户配置的输出和思考语义。

- 必须保留固定任务契约、当前用户问题/页、完成它所需的源区域、最新人工纠正和未闭合工具轮次。
- 可裁剪的是无关检索、重复工具输出、旧对话细节、过时摘要；按完整轮次/区域裁剪，不截断 JSON 或拆散 tool call/result。
- 本次内容本身过大时，由业务分块或明确报容量不足；公共传输层不得偷偷截掉半页文字或降低图片精度。
- 长聊天在预算内追加完整历史，保留前缀；接近高水位后批量压缩，回落到低水位，再开始新的稳定段。
  可先以 80%/60% 作为实验值，不固化为所有任务的容量标准。
- 不每条消息滑动删除最旧一条，也不每页重新生成整份摘要。压缩会付费并改变缓存前缀，应一并核算。
- 压缩结果要保留人物、否定、时间线、用户约束和未完成事项，并记录覆盖范围与原始来源。摘要失败不能替换旧快照。
- 记忆只在对应响应通过业务校验后写入；取消、无效 JSON、未完成翻译和迟到结果不得污染本书记忆。

不能只看压缩后更短：保留一段仍相关且便宜的缓存历史，有时比立刻付费摘要更划算。
同时，命中历史仍占模型容量并可能增加输出推理耗时，不能无限增长。

## 翻译的本书记忆

一本书维护一套翻译资料，按语言对隔离；请求只取需要的范围。
固定核心术语和称呼优先稳定复用，临时词条按相关性选择放后部，避免全书 500 条词典反复变化。

- 每页/片段原文、译文按真实章节和页面顺序保存来源及摘要，不按网络完成顺序推进语境。
- 漫画自动翻译允许预加载乱序完成。只选择目标页之前可用的语境；不为等缺失前页而阻塞整个队列，
  也不隐式补翻未请求页。跨页背景不足时仍可独立翻译。
- 分开稳定姓名知识与带时间线的人物关系/剧情；后者有适用章节范围，不把后续事件写进前页请求。
- 同一页重译替换该来源记录，不能重复追加；旧摘要包含被纠正页时标记失效或重建。
- 初版直接复用已验证的术语和前页对白，不额外调用记忆模型；剧情摘要作为后续独立切片。
- 图片识别阶段只带必要语言/术语；翻译阶段需要语义记忆；排版阶段只带确定的本页源文、译文和几何。
  仍保留单模型合并翻译/排版路线，不为此方案强制拆成更多请求。
- 生成缓存身份包含本次实际采用的记忆快照/增量摘要和来源修订；新记忆不应导致所有已发布译图撤下。
  显式重译才应用新的语境，离线重排继续零 AI 调用。

## 用量与验证缓存收益

先打通统计，再比较策略。建议响应增加可选用量，流事件增加对应事件；所有 exhaustive `when` 消费者同步处理。
未知字段使用 null/unknown，不用 0；价格缺失时显示 token，不伪造实际费用。

统一统计普通输入、缓存读取、缓存写入（可分生命周期）、总输入、输出、思考明细、TTFT 和总耗时。
字段有子集关系：思考通常属于输出明细；DeepSeek 的两种命中字段是别名；不能多算。
Anthropic 的普通 input 不含读/写；OpenAI 的 input 总量包含其明细，必须由协议适配器规范化。

流式统计不能依赖有正文的 chunk：可能在尾部 choices 为空、DeepSeek 最后一个带 finish_reason 的 chunk、
Anthropic 起始 message 与后续更新、Responses 完成事件中返回。
同一请求的累计快照取最终有效值，不把各快照相加；必要的增量按协议语义合并。
中断前没有完整用量就标为不完整，保留已报告的部分值；不能为补统计而重试翻译。
每个实际 HTTP 尝试分别计数；工具循环和纠错请求属于同一次用户操作的不同子请求。
用户操作内本地 dedupe/replay 不重复计数，网络重试也不能假定没有产生费用。

按供应商、模型、任务、本书/会话汇总：

```text
输入命中率 = Σ缓存读取 token / Σ总输入 token
输入费用 = 普通输入×单价 + 缓存读取×读单价 + Σ各生命周期写入×写单价
任务费用 = 输入费用 + 输出费用 + 其他服务费用（若可获取）
```

总输入、价格或分类不完整时不算完整费用；命中率用加总值计算，不能平均每请求的百分比。
实际账单仍以服务商为准，比较应包含摘要、重试和首次写入。
诊断记录计数、版本、来源摘要和耗时；不持久化密钥、完整私聊、base64 图片或思考全文作为统计日志。

## 实施顺序和验收

1. **公共用量与能力适配**：扩展可选响应/流事件，三类 Handler 覆盖流式和非流式；已知服务按能力设置缓存参数，
   未知服务不附加字段。先保留业务提示原样，建立对照统计。
2. **稳定前缀与预算规则**：实现可测试的组装/预算规则，先接小说翻译、漫画翻译和聊天；
   移走动态 system 片段，适配显式边界，保留原有结果解析、取消和存储。
3. **本书翻译记忆**：先做术语快照和跨页对白来源索引，验证预加载乱序与重译修订；后续再加可控的增量摘要。
4. **聊天压缩和其他入口**：用完整工具轮次预算替代条数截断，保存覆盖范围明确的摘要；逐个接文本工坊、摘要和配音。
5. **简短 UI**：在现有过程面板显示输入、命中、输出与耗时；高级诊断再展示裁剪范围和缓存能力，避免新增大量参数开关。

每个阶段单独可回滚，不为了上下文方案同时迁移 Room、设置 UI、模型协议与 Gradle 模块。
原生显式缓存默认选择短期且可复用的块，不主动做付费预热或为一次性页面设置长生命周期。
长期缓存只有在支持明确、复用行为与价格数据足够时再开放。

最小验证集应包含：

- 同样快照、不同页只改变后缀；Map 原始插入顺序不同不改变已编译稳定快照；人工纠正及时改变请求。
- 小模型/中日文/多图输入预留输出空间；必需块超限明确失败；工具调用与结果不被拆散。
- DeepSeek 别名去重、各协议缺失/最终/累计用量、空 choices 尾块、取消和重试计数。
- 自定义兼容服务无额外未知字段；Anthropic 显式边界不落在变化的页面；OpenAI 不同接口/模型参数互斥。
- 不同书籍、语言、账号配置之间不串记忆；乱序页、缺前页、重译、删除、恢复、迟到结果均保持来源一致。
- 缓存命中不改变翻译结果校验、现有缓存发布和仅重排零 AI 行为。
- 使用固定样本，对比冷请求、相同前缀的后续请求、语义资料更新和压缩后的真实用量、质量与费用；
  不用 Mock 证明实际缓存命中，不承诺固定节省比例。
