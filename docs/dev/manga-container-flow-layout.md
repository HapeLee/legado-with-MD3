# 漫画容器、对白分组与边界约束方案

状态：2026-10-27 的历史调研方案。2026-10-28 源码已有本地检测归属、持久化气泡内部掩膜、
连接内部按检测中心分区及形状约束排版，局部几何版本已升至 8；本文下方“当前代码的具体缺口”
记录的是当时基线，不能继续作为当前源码现状。
显式 Flow、AI 源行／字形样本、安全矩形和原图 ROI 精读已在后续切片接入；实际范围见
[AI 气泡精读、字号校准与本地排版方案](manga-ai-geometry-refinement.md)。

## 目标与范围

两个圆形气泡即使部分重叠、相连或承载同一句话，也应保留两个物理容器和两个排版区域。
译文需要按阅读顺序连贯，不能在每个气泡重复整句。每个排版矩形与实际绘制的笔画、描边均应位于
所属容器的安全内部，不跨越圆弧、凹口、相邻气泡或文字框边线。

沿用当前按书缓存、原图不变、成功后发布、已有译文可重排的行为。默认不增加 AI 请求轮次，
不在这个切片同时引入新 Gradle 模块、替换 OCR 或接入大型分割运行时。

## 当前代码的具体缺口

- `MangaBubbleGeometry.findBubble` 要求长宽比至少约 1.4，接近圆形的容器被跳过。
- 同一候选背景中出现其他已知文字区域时直接放弃恢复，无法表达两个气泡的实例归属。
- 背景采用连通区域查找；两个相连气泡的内部可能本来就是一个连通区域，不能据此判定只有一个容器。
- 每行只保存最左／最右边界，凹形、多段区间或内部隔线可能在取包络时丢失。
- `MangaTranslatedRegion` 同时承担文本和单个排版区域，没有容器标识、跨气泡对白分组或显式组内阅读顺序。
- 提示词虽然要求不同气泡分开，但没有表达“一句话分属多个气泡”的结构。
- `MangaTextLayout.draw` 裁剪到 `layoutBox`，并未裁剪到实际气泡轮廓。
  `PATCH` 遮盖和最终 ROI 贴回也以矩形为主，需要一起修改。
- `planLayout` 会保留能放下的旧框，并对框间重叠作矩形收缩，但没有所属容器的轮廓硬约束。

因此只删除圆形过滤或继续修改提示词不足以解决问题。

## 研究依据与推论

[Manga109-v2026，Type 5](https://arxiv.org/html/2605.21182v2#S3.SS2)
将多个连通气泡标注成单个文字框列为分割不足，修订时按独立气泡拆分。
这支持保留物理实例，但不直接提供本工程的对白分组或排版算法。

[OpenCV 标记分水岭教程](https://docs.opencv.org/4.13.0/d3/db4/tutorial_py_watershed.html)
展示距离变换与标记分水岭分离相接对象，同时说明噪声会造成过度分割，实例仍可能分错。
可借鉴“多个可靠种子约束分割”，不能把二值连通域或固定阈值当成气泡数量的真值。

[The Manga Whisperer，第 4 节及附录 B](https://arxiv.org/html/2401.10224v3)
将阅读顺序作为检测后的独立任务，并利用相对位置关系处理重叠布局。
其详细图算法针对面板；用于本工程气泡的排序属于待验证的设计推论，不声称可以直接照搬。

## 数据职责

把三个概念分开，均使用稳定标识关联：

| 概念 | 负责的事实 | 不负责的事实 |
| --- | --- | --- |
| Container | 一个可见气泡／旁白框实例及其安全边界、遮挡归属、边界可信状态 | 句子是否完整 |
| Region | 原文、译文片段、原文笔画锚点、所属容器 | 将两个容器的坐标合并 |
| Flow | 一段连贯对白及有序 Region 标识 | 擦字或气泡外形 |

建议向现有 `regions` 增加可选 `containerId`，Plan 增加可选的 `flows`。
一个 Flow 保存唯一的有序 `regionIds`，不要又在每个 Region 保存一份可冲突的组内序号。
现有 Region 的 `translation` 仍保存对应的译文片段；整段译文从有序片段派生，不再保存第二份可能不一致的正文。
缺失 Flow 的历史区域按独立块兼容，不自动宣称已经恢复语义关联。

示意契约（省略现有坐标和方向字段）：

```json
{
  "regions": [
    {"id":"r0","containerId":"b0","original":"如果今晚还下雨，","translation":"If it keeps raining tonight,"},
    {"id":"r1","containerId":"b1","original":"我们就改天出发。","translation":"we will leave another day."}
  ],
  "flows": [{"id":"f0","regionIds":["r0","r1"]}]
}
```

一次 AI 请求按 Flow 联合理解和翻译，输出各气泡应显示的连续片段。不能把整句译文复制进两个框，
也不能按字符数把译文机械劈半。句法允许跨源气泡重新组织表达，但组内目标阅读顺序必须连贯。
`containerId` 是实例提示，客户端仍需用源笔画与本地轮廓验证关联，不能相信一个错误的大容器标签。

契约校验需要覆盖：Region／Container／Flow 标识唯一、引用存在、同一 Region 不重复加入多个 Flow、
组内标识不重复、没有缺译或多译区域。不同说话者、不同对白不能仅因气泡相邻就自动归为同一 Flow。

## 上下左右与阅读顺序

区分页面／分镜顺序、气泡顺序、原文字符方向和目标文字排版方向。
竖长气泡仍可横排；英文译文也不意味着原漫画采用从左到右的分镜顺序。

优先级建议：

1. 显式 Flow 顺序，以及用户明确指定的原作阅读方向。
2. 同一分镜内的上下、左右相对关系和文本锚点。
3. 页面结构和语义上下文协助处理斜向、重叠及冲突关系。

按书提供“自动／原作从右到左／原作从左到右”的覆盖选项可作为后续 UI 切片；
不要将翻页手势、音量键反转或目标语言直接作为语义阅读顺序。
不能对所有气泡只按 X 或只按 Y 排序。几何推导发生冲突时保留不确定状态，避免用任意排序改变原话。

## 容器分割与重叠

先区分三类图像，避免把它们当作同一种重叠：

1. 外接矩形重叠，但两个实际轮廓仍独立：分别建立实例，不按矩形相交或 IoU 合并。
2. 两个气泡内部连通，形成双圆／葫芦形：以各自原文锚点为种子，结合内部距离峰值、轮廓凹口和窄连接区划分实例。
3. 前后气泡相互遮挡：使用可见边界和源文字判断像素归属；不能让后方容器的排版盖到前方气泡或其边框。

本地候选算法为标记分水岭或等价的带种子区域划分。已有两个可信文字锚点时优先用它们，
轮廓距离峰值只作辅助，防止噪声把一个气泡切成多个，或大幅重叠导致峰值合并。
未可靠识别第二个实例时，不把合并后的大白区直接授予一个大排版框。

原文检测只给出一个合并块时，要先恢复每个容器的原文跨度和顺序，再做联合翻译。
本地 ML Kit 路径需要保留 line／element 的文字与框的对应关系，当前只有块原文和行擦字框还不足以可靠重组。
视觉 AI 路径可直接要求“按物理气泡拆 Region，按语义关联 Flow”，不必为此增加第二次 AI 调用。

不在未评估 APK 体积、许可证、内存、取消延迟及真机耗时前直接加入 OpenCV／大型实例分割模型。
可先在现有受限预览和像素预算内验证算法；无法可靠判断边界时显式保留未解决状态。

## 排版边界必须是硬约束

不能只检查原文框或气泡外接矩形的四个坐标。建立每个实例自己的内部掩膜 `M`，
排除边框、邻居和遮挡区，再按描边、缩放误差与安全距离向内收缩，得到 `S`。

候选排版矩形 `R` 的接受条件是：

```text
R 的每个像素都在 S 内
outsidePixelCount(R, S) == 0
```

可用“掩膜外像素”的积分图快速校验候选矩形；这比每次逐像素重扫更适合字号和区域搜索。
预览阶段测量后，还需在原尺寸映射时保留安全余量，防止坐标舍入让描边越界。

仅检查四角也不能处理凹轮廓。已验证的几何反例：两个圆心为 `(100,100)`、`(220,100)`，半径均为 80；
矩形为 `[60,40]–[260,160]`。四角均在双圆并集内，但上边中点 `(160,40)` 在并集外；
按像素中心采样，整个矩形有 92 个像素位于外部。这正是重叠轮廓不能压成一个包络框的原因。

排版顺序：安全区域内寻找足够空间 → 优先原字号 → 在合法区域内换行或微调有序片段分配 → 缩字 → 明确报告放不下。
不靠越过气泡边框解决溢出。局部移动译文片段时必须保持 Flow 的顺序、完整性和 Unicode 字素边界，
优先句子／词边界，不能重复、遗漏或打散 emoji；这需要独立于物理框的文本信息。

矩形包含校验通过后，绘制仍按实例轮廓裁剪作为最后保护。
该约束必须同时用于本地绘字、覆盖底色、背景修复的贴回和最终分块 PNG 合成。
单纯最后裁剪不够，否则只是把溢出的文字截掉。两容器的有效贴回区域应有明确归属，防止后处理把另一气泡的译文覆盖。

掩膜不能仅保存每行最左和最右点；需保存轮廓或支持一行多段的区间表示，以保留凹口和内部隔线。
领域数据使用归一化坐标／可序列化掩膜描述，Android `Path` 等类型仅在渲染侧构造。

## 落地顺序与兼容

1. 建立双圆相接／重叠／遮挡的复现用例，增加容器标识、Flow 契约与完整性校验。
2. 提示词按物理容器拆分，联合翻译但返回分片；支持显式阅读顺序，仍保持每窗口一次分析请求。
3. 支持圆形、矩形、胶囊的单实例安全掩膜，接入整个合成链路的硬边界。
4. 对连通双气泡验证带标记分割，补充斜向、遮挡和复杂边界；不确定时保留旧发布结果／明确提示需要重新识别。

旧结果已经有两个文字块时，可以从原图补容器边界并重排，不需要重新翻译。
旧结果只有一个合并文字块时，不能一概承诺免 AI 自动拆分：缺少原文跨度、语义分组或阅读顺序时需明确重新识别／翻译，
或待未来人工校正功能指定；不能在“仅重新排版”中静默增加付费调用。成功前仍保留上一份译图。
分组与边界快照按分析窗口持久化，局部几何与渲染缓存均需更新版本，不能复用旧单框 ROI。

## 竖排原文列数优先

竖排区域保存可选 sourceColumnCount（1..64），AI 按实际原文列数填写；提示词要求保留原文分列换行。
旧计划重新排版时，优先采用原文明确换行或 OCR 源行的横向分组；缺失时在原图文字框内作墨迹投影估算，
不从译文的行数或气泡长宽比推断。投影仅是缺少元数据时的估计，复杂底纹可能使其不可用。

本地形状排版先在正常字号范围内按原文列数求解；失败再使用既有自适应布局和应急缩字。
AI 排版在原文列数明确且返回列数不符时，重新组织绘制列，并校验译文字符、词边界与阅读顺序，
沿用既有区域和样式；适配不了时保留兼容布局。正常纵向排版且已匹配原文列数时，AI 换行保持原样。
最终绘制按适配区域后的预计尺寸检查多短列组成的扁平条带，不能因已有列数元数据而跳过；原文列数试排允许进一步缩字，
不再以 65% 字号下限使重排失败后退回扁平布局。短句不足六个字形时不应用长句条带修正；对于高宽比至少 2 的窄长区域，
五个及以内显示字形的短中文／标点使用单列，合并称呼和省略号，避免每个字变成一列。
只有原文已明确识别为竖排、原文字框和排版框都窄长且译文适合 CJK 竖排（或仅标点）时，
才在绘制时纠正误报的横向目标方向；仅有高气泡而原文横排时保持横排。
上述修正不改写存储的译文、AI 原始行列或对齐样式，仍检查字符、词边界和绘制范围。
宽框内已匹配原文列数且宽度适配的多列排法保持原样，不能仅凭视觉宽高比就将其收成两列。
渲染版本 22、重新排版版本 21。旧译图保留，显式重新排版应用此规则。
